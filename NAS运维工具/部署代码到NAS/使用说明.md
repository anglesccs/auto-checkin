# 部署代码到NAS — 使用说明

把本机改动推上飞牛 NAS，并重建 docker 镜像。**双击 `部署代码到NAS.bat` 即可。**

## 1. 是不是单 BAT？

**是。** 只需要这一个 `.bat`，没有额外的 .py / 配置文件。

唯一的"依赖"是**要部署的源码**（`checkin/ static/ Dockerfile docker-compose.yml requirements.txt .dockerignore`）。
脚本按下面的顺序自动找源码：

1. `deploy.conf` 里的 `SRC_OVERRIDE=`（想固定某个目录就填这里）
2. 从本文件夹**逐级向上最多 6 层**，找同时含 `checkin\web.py` 和 `Dockerfile` 的目录
   → 所以本文件夹放在项目里（`自动签到\NAS运维工具\部署代码到NAS\`）时，永远用**项目最新代码**，不会用到副本
3. 本文件夹下的 `src_snapshot\`
   → 只有把整个文件夹拷到项目外（U 盘、别的机器）时才走这一步

> `src_snapshot\` 是源码副本，用来让本文件夹能整包独立移植。
> 只要文件夹在项目内，它就**不会被使用**；在项目外用它部署前，建议先用最新的 `checkin/ static/ ...` 覆盖一遍。

脚本每次运行都会打印实际使用的源码目录（`Code : ...`），跑之前扫一眼就知道推的是哪份代码。

## 2. 交互问答（回车 = 用 `[]` 里的默认值）

| 序号 | 问题 | 说明 |
|---|---|---|
| 1 | `NAS 的 IP 或主机名` | **必填**（脚本不含任何内置主机；示例 `192.168.x.x`） |
| 2 | `SSH 端口` | 默认 `22` |
| 3 | `登录方式` | `1` = SSH 密钥免密（默认）；`2` = 密码 |
| 4 | `SSH 用户名` | **必填**（示例 `user`） |
| 5 | `SSH 密码` | **仅选 2 时出现**，输入不回显，不写盘 |
| 6 | `远程项目目录` | 默认 `/vol2/1000/docker/auto-checkin` |
| 7 | `控制台端口` | 默认 `8080`，只用于最后打印控制台地址 |

回答记到同目录 `deploy.conf`（**不含密码**），下次免重复输入。

### 密码方式（第 3 题选 2）的两种表现

| 本机情况 | 表现 |
|---|---|
| 装了 PuTTY（有 `plink.exe`） | 全自动：脚本自己用密码完成上传 |
| 没装 plink | 只能用 OpenSSH，**OpenSSH 不接受脚本喂密码**，于是它自己弹一次密码提示，在那里输一次即可（因为整个上传+重建只调 1 次 `ssh`，所以只问 1 次） |

> 想省心就用密钥登录（例如 `<SSH用户名>@192.168.x.x` 配了免密），选 1 全程无密码。

## 3. 它到底做了什么

1. `tar` 打包 `checkin static Dockerfile docker-compose.yml requirements.txt .dockerignore`
   （在源码目录内打包成相对路径的 `auto-checkin-src.tgz`，再挪到 `%TEMP%`，兼容 GNU tar / bsdtar）
2. 一条 `ssh` 把包喂过去：`cd <远程目录> && tar xzf - && docker compose up -d --build && docker ps`
3. 打印容器状态行

**为什么必须一条 ssh、必须 `--build`**：
- 只 `docker compose up -d` **不会**拾取代码改动，必须 `--build` 重建；
- 合成一条命令是为了让密码模式只问一次密码。

## 4. 成功判据

- 结尾出现 `[DONE] deployed.`
- 上面有一行 `auto-checkin Up ...`
- 然后打开 `http://<NAS IP>:8080`，账户表里 WorkBuddy 行显示状态文字而不是红色报错

预计 1~3 分钟（pip 层有缓存时通常 20~60 秒）。

## 5. 命令行参数（可选，跳过交互）

```bat
部署代码到NAS.bat
部署代码到NAS.bat <SSH用户名>@192.168.x.x
部署代码到NAS.bat <SSH用户名>@192.168.x.x /vol2/1000/docker/auto-checkin
```

参数只是**预填**默认值，仍然会走问答（一路回车即可）。

## 6. 常见失败

| 提示 | 原因 / 处理 |
|---|---|
| `[FAIL] Cannot find the code to deploy.`（找不到要部署的代码） | 没有找到含 `checkin\web.py` + `Dockerfile` 的目录。把文件夹放回项目内，或把源码拷进 `src_snapshot\`，或在 `deploy.conf` 里写 `SRC_OVERRIDE=项目根目录` |
| `[FAIL] packing the source failed.`（打包源码失败） | 看上面的 tar 报错；确认源码目录里那 6 个条目都存在 |
| `[FAIL] upload / rebuild failed`（上传 / 重建失败） | 密码/用户/端口不对；远程目录不存在；NAS 上 `docker compose` 不可用；NAS 不可达 |
| `[FAIL] 未找到 ssh.exe` | 设置 → 应用 → 可选功能 → 添加「OpenSSH 客户端」 |
| 重建后现象没变 | 确认状态行是 `Up`；再确认控制台上方是不是缓存页面（Ctrl+F5） |

## 7. 备注

- `data/` 是外挂卷（`./data:/app/data`），重建**不会**丢账户、设置、历史。
- 脚本出错时会把 `%TEMP%\auto-checkin-src.tgz` 和源码目录里的临时包删掉，不留垃圾。
- 手工等价命令（含中文路径更稳的 tar 管道写法）见项目根 `系统说明与部署.md`。
