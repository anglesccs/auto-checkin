# 同步登录信息到NAS — 使用说明

把**本机** Trae CN / WorkBuddy / Qoder 的登录态导入 NAS 上的自动签到服务。
用于：控制台报 `HTTP 401：accessToken 已失效`，或账户表「凭据有效期」列标红「已过期」。

## 1. 是不是单 BAT？

**不是。** 这个 `.bat` 必须和下面几个文件放在**同一个文件夹**（已经一起放好了，别拆开）：

```
同步登录信息到NAS/
├─ 同步登录信息到NAS.bat          <- 双击这个
├─ sync_credentials.py            <- 提取本机登录态 + 上传
├─ extract_credentials.py         <- 读取 Trae / WorkBuddy 客户端凭据文件（被上面那个 import）
├─ extract_qoder_credentials.py   <- 读取 Qoder 登录态 + 生成机器指纹（被 sync import，也可单独运行）
├─ install-deps.bat               <- 装 Python 依赖，只跑一次
└─ sync.conf                      <- 首次运行自动生成，记住地址
```

外加两个运行环境前提：

| 前提 | 说明 |
|---|---|
| Python 3.9+ | 没有就先去 python.org 装，安装时勾「Add python.exe to PATH」 |
| `requests` / `PyYAML` / `pycryptodome` | 双击 `install-deps.bat` 一次装好 |
| **WorkBuddy 客户端正在运行** | 新版 token 是 AES-256-GCM 加密的，**解密密钥只存在于运行中的客户端进程内存里**。客户端没开 → 这条凭据会被跳过 |
| Qoder 客户端已登录（在运行更好） | 登录态在本机文件里（DPAPI 加密），不要求客户端运行；运行中可保证指纹 / 域名探测更顺 |

## 2. 交互问答（回车 = 用 `[]` 里的默认值）

| 序号 | 问题 | 说明 |
|---|---|---|
| 1 | `NAS 的 IP 或主机名` | **必填**（脚本不含任何内置主机；示例 `192.168.x.x`）。填的是**跑服务的那台机器**，不是 SSH 地址 |
| 2 | `控制台端口` | 默认 `8080`，拼成 `http://<IP>:<端口>` |
| 3 | `Web 密码（没有则留空）` | 服务端设了 `WEB_PASSWORD` 才填；**留空**则由 Python 脚本自己再问一次（输入也不回显） |

回答记到同目录 `sync.conf`（**不含密码**）。

命令行也可带参数：`同步登录信息到NAS.bat 192.168.x.x 8080 [web密码]`

## 3. 执行流程

1. 读本机 Trae CN / TRAE SOLO CN / WorkBuddy / Qoder 客户端的登录态（**只读**，不动客户端文件）
2. 同一账号（`user_id` / `uid` 相同）只保留有效期最长的一份；Trae 会带上客户端本地存储中的**真实设备号**（`device_id` / `machine_id`，领取接口要求为客户端真实签发，勿手工编造）；Qoder 会顺带生成机器指纹（中国版必须）并探测 API 域名
3. `POST` 到服务的 `/api/accounts/trae_client`、`/api/accounts/workbuddy`、`/api/accounts/qoder`
4. 服务侧立刻回查官方接口，验证登录态是否有效并打印昵称和实时余额

## 4. 成功判据

```
-> 导入成功（<昵称>），登录态有效，当前余额 <数字>
--------------------------------------------------
同步完成：2/2 个账户已导入远端服务
```

每次成功会打印**实时余额**，可以用来交叉核对控制台上的数字。

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `导入失败：Not Found` | 本机设了 `http_proxy` / `https_proxy`（公司代理、抓包工具、容器网关），requests 把内网请求也交给了代理，代理对未知主机回 404。**本版已修**：目标为内网地址时自动 `trust_env=False` 绕过代理，日志会打印「目标为内网地址，已绕过系统代理」。确实需要走代理时设 `CHECKIN_USE_PROXY=1` |
| `跳过 [xxx]：token 已加密存储，且 WorkBuddy 客户端未在运行、无法解密` | 打开 WorkBuddy 客户端（保持运行），再跑一次 |
| `Qoder 提取异常` / Qoder 提示指纹生成失败 | 确认本机装有 Qoder 客户端且已登录；单独跑 `python extract_qoder_credentials.py` 看详细输出。中国版账户（qoder.com.cn）必须有指纹，否则服务端拉不到活动列表 |
| `[FAIL] Python modules missing` | 双击 `install-deps.bat` |
| `未在本机找到任何登录态` | 本机从没登录过 Trae / WorkBuddy / Qoder，或客户端数据目录被清理过 |
| `[WARN] the script exited with code 1` | 有账户没导成功，往上翻日志找 `-> 导入失败` 那一行；只失败一部分时其余的仍然有效 |
| 导入成功但控制台仍显示过期 | 服务端余额/状态查询失败时会打印「已导入，但状态查询失败」，把那一行发出来排查 |

## 6. 什么时候**不需要**重跑

- TRAE / Qoder 那行有效期旁标了「可自动续期」→ 过期也能靠 `refresh_token` 自动续，可以先观察。
- 账户表显示 `-`（没有 `expires_at`）或「网页会话」→ 正常，不是过期。

## 7. 安全提示

- 本工具只**读取**客户端凭据，不改动、不删除。
- 密码不写入任何文件；上传走的是本机 → NAS 的内网 HTTP，服务默认无鉴权，**不要把这个端口暴露到公网**。
